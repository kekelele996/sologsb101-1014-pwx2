# 林业站权属台账 × 项目部修复地块 接账口径说明

本说明对应数据库结构 **v3**：在原有「修复地块（Plot）—苗木批次—栽植—验收—补植」之外，
新增林业站两本数据：**宗地（Parcel）** 与 **宗地重划记录（ParcelAdjustment）**。

- 林业站那本账（`parcels` / `parcelAdjustments`）只管：**宗地编号、权属面积、四至**，以及并宗/分宗谱系。
- 项目部这摊（`plots` 及以下）只管：**修复地块**及其下的**栽植记录、验收测次、补植计划**。
- 两本账通过 `plots.parcelCode → parcels.parcelCode` 与重划记录里的新老宗地/新老地块映射连接。

---

## 1. 并宗后成活率分母：按两老地块「栽植总株数相加」，不按权属面积加权（已定）

**决定：分母 = 各老地块栽植总株数直接相加；分子 = 对齐测次的成活株数相加。**

理由：

1. 成活率的定义是「**活下来的植株 / 实际栽下去的植株**」，株数是可直接相加的物理量，
   相加后仍然是一个真实的存活比例：`(a活 + b活) / (a栽 + b栽)`。
2. 按权属面积加权（`r_a·S_a + r_b·S_b` / `S_a + S_b`）混入了两宗地的**立地差异与实际栽植密度差异**。
   权属面积是林业站的确权面积，不等于项目部实际作业面积；密度不同时，面积加权算出来的不是真实存活率，
   会系统性地把「栽得密、死得多」的地块权重做大或做小，口径失真。
3. 面积在并宗里仍要核对，但只用于**权属守恒校验**（新宗地面积 ≈ 老宗地面积合计，容许 5% 测量误差），
   不进入成活率公式。

**测次对齐规则（分子怎么加）**：同「测次号 + 验收日期」在每个老地块各有一条，才把成活株数相加；
任一老地块缺该测次、或同测次验收日期不一致，则**该测次挂起复核**（`roundMisaligned`），
不参与「最新成活率 / 建议补植株数」。平均株高按各老地块成活株数加权汇总。

示例（南滩并宗）：老 1 号栽 2000、老 2 号栽 2600 → 分母 **4600**；
第 2 测次（同日 2024-10-15）成活 1700 + 2160 = 3860 → 成活率 **83.9%**。

## 2. 分宗后历史验收测次：留在老地块只读，不划归任一新地块（已定）

**决定：分宗生效日之前的历史验收测次，一律保留在被拆老地块（`parentPlotId`）名下只读展示；
两个新地块都不继承这些测次。自生效日起，各新地块各自从第 1 测次重新起测。**

理由：

1. 分宗前的测次是在**整块老地**上做的整体/抽样调查，成活株数没有、也无法按新界线物理切分到两班组；
   无论「全判给某一侧」「按面积劈一半」还是「两侧复制一份」，都会制造虚假精度或重复计数。
2. 因此历史数据是**分宗前整块地的共同档案**，最诚实的做法是留在老地块、只读、可追溯，
   并在新地块视图中标注「分宗前历史见老地块」。
3. 分宗后的成活率与补植责任以班组为界，用各新地块**生效日后**各自新栽、新测的数据计算，责任清晰。

栽植记录同理：分宗前的栽植留老地块（只读）；新地块生效日后的新栽直接挂新地块。

## 3. 对不上的挂起复核；挂起期间不出补植计划

一条重划记录保存时自动跑接平校验（`checkAdjustment`），任一不过即置 **挂起复核（hold）**：

| 原因码 | 触发条件 |
| --- | --- |
| `missingPlot` | 映射的项目部老/新地块数量不对或地块不存在 |
| `missingOldParcel` / `missingNewParcel` | 新/老宗地编号在林业站台账里缺失 |
| `areaMismatch` | 新老权属面积合计偏差超过 5%（`PARCEL_AREA_TOLERANCE`） |
| `roundMisaligned` | 并宗时某测次在各方缺失或验收日期对不上（记录具体挂起测次 `heldRounds`） |
| `manualHold` | 人工标记挂起，待两站共同复核 |

挂起的后果（`replantGate` 统一收口）：

- 相关承接地块**不出补植计划**：验收台「生成补植计划」、补植页「新建补植计划」都会被拦截并提示原因；
- 并宗时挂起测次不参与最新成活率与补植测算，界面打「挂起复核中」标记；
- 历史栽植/验收**仍只读可查**，不删不改。

复核通过后在权属台账页点「复核通过」（或改对数据后重新保存）即恢复 `linked`，恢复出补植计划。

## 4. 升级回填：已有数据没有宗地归属时怎么办

老用户库里此前**没有任何宗地归属**。v3 升级迁移（`db.version(3).upgrade`）规则：

1. **按原地块编号回填历史宗地**：为每个已有修复地块，用其原 `plot.id` 作为历史宗地编号
   （`parcelCode = plot.id`）补一条 `source: 'legacyBackfill'` 的宗地，权属面积取该地块当时面积，
   四至无历史可考先留空待林业站补登；地块 `lineageRole='normal'`、可正常使用。
2. **回填不出的只读保留**：原地块编号缺失/为空、无法据此造出宗地编号的个别地块，
   `parcelCode` 留空并置 `readOnly=true`：数据原样保留、只读可查，但不允许新增栽植/验收，也不出补植计划；
   待林业站确认真实宗地编号后人工关联再放开。
3. 林业站正式导入的宗地 `source='forestry'`，与回填宗地通过重划记录衔接；
   并宗/分宗由用户在权属台账页登记，登记后自动把老地块置 `legacy`（只读）、承接地块置
   `mergeTarget` / `splitChild`。

## 5. 地块谱系角色（plots.lineageRole）

| 角色 | 含义 | 可写 | 成活率口径 |
| --- | --- | --- | --- |
| `normal` | 常规地块，1:1 挂一宗现行宗地 | 是（需有 parcelCode） | 本地块 成活/栽植 |
| `mergeTarget` | 并宗后的合并地块 | 业务可写；**不直接录测次** | 跨老地块按株数聚合 |
| `splitChild` | 分宗后某班组承接的新地块 | 是 | 仅生效日后本地块数据 |
| `legacy` | 被并宗/分宗替代的老地块 | **只读** | 保留分宗/并宗前历史 |

> 设计上不物理搬迁、不复制老栽植/老验收：历史行始终挂在老地块，
> 并宗承接地块通过重划映射**实时聚合**，分宗承接地块只看自身新数据。避免一份历史被重复计数。
